[STEP 2: KEYPAIR GENERATION & ADDRESS DERIVATION]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m wallet.cli keygen --out dev.key --pub-out pub.json

SPOKEN NARRATION:
"First, we run 'keygen' to generate an Ed25519 keypair using the operating system's secure CSPRNG.
Notice the security controls:
The private key is written to 'dev.key' with restricted 0600 file permissions and an explicit 'TEST ONLY - DO NOT USE ON MAINNET' warning header.
The public key is exported into 'pub.json', along with its derived Base58Check address.
The address begins with prefix byte 0x6f for course testnet, followed by the public-key hash and a 4-byte double-SHA256 checksum."

--------------------------------------------------------------------------------
[STEP 3: ADDRESS DERIVATION FROM RAW PUBLIC KEY]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m wallet.cli address <PUBKEY_HEX>

SPOKEN NARRATION:
"To verify that address derivation is deterministic and independent, we pass the raw hexadecimal public key to the 'address' command.
Notice that it derives the exact same Base58Check address as the keygen command."

--------------------------------------------------------------------------------
[STEP 4: CANONICAL TRANSACTION SIGNING]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m wallet.cli sign --key dev.key --tx sample_tx.json --out signed_tx.json

SPOKEN NARRATION:
"Now, we sign a transaction paying 1,250,000 atomic units to Bob on 'course-testnet'.
Before signing, our wallet serializes the transaction into RFC-8785 canonical JSON bytes.
This guarantees that regardless of whitespace or key ordering differences, the signature is computed over the exact deterministic byte sequence.
The signature is appended to the payload and saved to 'signed_tx.json'."

--------------------------------------------------------------------------------
[STEP 5: INDEPENDENT TRANSACTION VERIFICATION (SUCCESS PATH)]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m wallet.cli verify --signed-tx signed_tx.json --state-db state.json

SPOKEN NARRATION:
"Next, an independent node or validator verifies this signed transaction.
The verifier reconstructs the canonical message bytes, checks the Ed25519 signature against the sender's public key, verifies that the public key matches the sender address, and validates the nonce.
The output shows: TRANSACTION VERIFIED! All cryptographic checks pass."

--------------------------------------------------------------------------------
[STEP 6: FRAUD DETECTION: TAMPERED AMOUNT REJECTION]
--------------------------------------------------------------------------------
COMMAND TO RUN:

SPOKEN NARRATION:
"To demonstrate attack resilience, what if an adversary alters the transaction amount from 1,250,000 to 9,999,999 units?
When we verify the tampered transaction, the node immediately detects signature mismatch and rejects it with: InvalidSignature! No funds can be stolen."

[STEP 7: REPLAY ATTACK PREVENTION]

COMMAND TO RUN:
