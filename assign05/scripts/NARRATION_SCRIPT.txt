SPOKEN NARRATION:
"First, we inspect the binary block header format using 'hex-dump'.
Notice that every block header is packed into an exact 116-byte fixed-size binary struct:
- 4 bytes for version,
- 32 bytes for previous block hash,
- 32 bytes for the transaction Merkle root,
- 8 bytes for 64-bit UNIX timestamp,
- 32 bytes for the big-endian Proof-of-Work target,
- and 8 bytes for the 64-bit nonce.
The block hash is the double-SHA256 digest of these exact 116 serialized bytes."

[STEP 4: FORK SIMULATION & CHAIN REORGANISATION]
--------------------------------------------------------------------------------
COMMAND TO RUN:

SPOKEN NARRATION:
"Now, we simulate two competing miners producing a blockchain fork and watch how the consensus engine resolves it.
First, Genesis block is initialized.
Miner A mines Block 1A on top of Genesis at standard difficulty.
At the same time, Miner B mines a competing Block 1B on Genesis, but Miner B mined at 4x higher difficulty, which means Block 1B possesses 4 times higher cumulative work.
When Block 1B is submitted to the chain manager:
Even though both branches are at equal Height 1, the consensus engine detects that Branch B has strictly greater cumulative work!
The node automatically executes a chain reorganisation: it disconnects Block 1A, restores its spent UTXOs, connects Block 1B, and sets the active tip to Branch B.
This proves that cumulative work governs blockchain finality."
