[STEP 4: AVALANCHE EFFECT & HAMMING DISTANCE]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m hashlab.cli avalanche --text "Alice pays Bob 10" --bit 7

SPOKEN NARRATION:
"Now, we demonstrate one of the core security properties of SHA-256: the Avalanche Effect.
Here, we flip just a single bit—bit index 7—in our input string.
We measure the Hamming distance between the original 256-bit hash and the mutated hash.
As we can see on the screen, changing a single input bit flipped approximately 128 bits in the final digest.
That is roughly 50% bit flip, satisfying strict avalanche criterion."

--------------------------------------------------------------------------------
[STEP 5: CANONICAL JSON DETERMINISTIC SERIALIZATION]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m hashlab.cli canonical-json "{\"recipient\":\"Bob\",\"amount\":10}"

SPOKEN NARRATION:
"Next is Canonical JSON.
In blockchains, transaction data must produce deterministic byte representations regardless of whitespace, formatting, or platform differences.
Our implementation applies RFC-8785 rules: keys are sorted lexicographically, whitespace is eliminated, floats are normalized, and strings are encoded strictly in UTF-8 NFC."

--------------------------------------------------------------------------------
[STEP 6: VISUAL DIFFERENCES & HASH SENSITIVITY]
--------------------------------------------------------------------------------
COMMAND TO RUN:
python -m hashlab.cli demo-differences

SPOKEN NARRATION:
"Here we demonstrate why visual similarity can be misleading in blockchain protocols.
First, line ending differences: LF versus CRLF produces completely different digests.
Second, Unicode normalization: the word 'café' in NFC precomposed form has 5 bytes, whereas in NFD decomposed form it has 6 bytes. Visually identical on screen, but they produce totally different hashes.
Third, JSON type differences: an integer 10 versus string '10' are distinct byte sequences.
Fourth, key order: raw JSON objects with different key order produce different hashes, but under our canonical JSON pipeline, they produce the exact same deterministic hash."
